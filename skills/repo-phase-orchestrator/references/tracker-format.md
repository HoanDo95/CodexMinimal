# Tracker Format

Tracker should record:
- phase
- status
- changed files
- verification commands
- quality gates required for the phase
- solution/system-design/QA evidence status when selected
- completed phase summary
- intent alignment: matched, partial, drifted, or blocked
- delivered outcomes mapped to the original intent
- remaining intent gaps
- failures
- fixes
- commit reference
- blockers
- next phase objective
- next phase dependencies from the completed phase
- execution workflow used
- whether scope drift occurred
- whether runtime state was refreshed

Keep tracker separate from plan.
